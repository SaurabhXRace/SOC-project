# Index & PowerShell Logging

### 1. Start Ubuntu Linux
Opened the Ubuntu Linux virtual machine to configure Splunk Universal Forwarder and prepare the log collection process.

---

### 2. Start Splunk Universal Forwarder

**Command:**
```bash
sudo /opt/splunkforwarder/bin/splunk start
```

**Description:**
Started the Splunk Universal Forwarder service on Ubuntu Linux to enable log collection and forwarding to the Splunk Enterprise server.

---

### 3. Configure the inputs.conf File

**Command:**
```bash
sudo nano /opt/splunkforwarder/etc/system/local/inputs.conf
```

**Description:**
Opened the inputs.conf configuration file using the Nano text editor with administrative privileges. This file is used to define log sources that Splunk Universal Forwarder monitors and collects.

---

### 4. Configure Linux Authentication Log Monitoring

**Configuration:**
```ini
[monitor:///var/log/auth.log]
disabled = false
index = linux
sourcetype = linux_auth
```

**Description:**
- monitor: Configured Splunk to monitor the Ubuntu authentication log file.
- disabled = false: Enabled monitoring of the specified log source.
- index = linux: Assigned collected authentication events to the linux index in Splunk.
- sourcetype = linux_auth: Defined a custom sourcetype to identify and categorize Linux authentication logs.

---

### 5. Save the Configuration

**Commands / Shortcuts:**
- Ctrl + O — Saved the configuration file.
- Enter — Confirmed the file name.
- Ctrl + X — Exited the Nano text editor.

**Description:**
Saved the updated log monitoring configuration in inputs.conf to apply the required changes.

---

### 6. Restart Splunk Universal Forwarder

**Command:**
```bash
sudo /opt/splunkforwarder/bin/splunk restart
```

**Description:**
Restarted Splunk Universal Forwarder to reload the updated configuration and apply the new log monitoring settings.

### 7. Test and Verify Linux Authentication Logging

To verify that the Splunk Universal Forwarder is successfully forwarding `/var/log/auth.log` events to Splunk Enterprise, simulate failed and successful authentication attempts and monitor them in the Splunk web interface.

---

#### Step 1: Simulate Authentication Attempts on Linux

Run the switch-user command with root privileges:

```bash
sudo su
```

1. Enter an **incorrect password** 3 consecutive times to trigger authentication failure logs.
2. On the next prompt, enter the **correct password** to log a successful privilege escalation.
3. Exit the root shell:
   ```bash
   exit
   ```

---

#### Step 2: Verify Index Ingestion in Splunk Enterprise

1. Log in to the **Splunk Enterprise Web UI**.
2. In the top navigation bar, click on **Settings** (`⚙`).
3. Under the **DATA** category, select **Indexes**.
4. Verify that the `linux` index exists and shows an incrementing **Event Count** and updated **Latest Event** timestamp.

---

#### Step 3: Search and Analyze Failed Login Events

1. Navigate to **Apps** > **Search & Reporting**.
2. Set the time range picker to **Last 15 minutes** (or **Real-time**).
3. Execute the following SPL query in the search bar:

```spl
index=linux sourcetype="linux_auth" "authentication failure"
```

**Query Breakdown:**
* `index=linux`: Filters events stored inside the dedicated Linux index.
* `sourcetype="linux_auth"`: Restricts the search to parsed Linux authentication logs defined in `inputs.conf`.
* `"authentication failure"`: Matches PAM and sudo failed authentication strings generated by invalid login attempts.

---

### 8. Configure Linux System Log (`syslog`) Monitoring

Extend the Splunk Universal Forwarder configuration to ingest general Linux system activity, service states, reboot cycles, and automated scheduled tasks (Cron jobs) from `/var/log/syslog`.

---

#### Step 1: Open the Inputs Configuration File

Edit the local inputs configuration file using administrative privileges:

```bash
sudo nano /opt/splunkforwarder/etc/system/local/inputs.conf
```

---

#### Step 2: Define the `syslog` Monitor Stanza

Append the new monitoring stanza below the existing `auth.log` configuration:

```ini
[monitor:///var/log/auth.log]
disabled = false
index = linux
sourcetype = linux_auth

[monitor:///var/log/syslog]
disabled = false
index = linux
sourcetype = linux_syslog
```

**Configuration Details:**
* `[monitor:///var/log/syslog]`: Specifies the path to the system log containing kernel, daemon, service, Cron job, and reboot events.
* `disabled = false`: Enables real-time log tracking for this source.
* `index = linux`: Directs the ingested syslog stream into the shared `linux` storage index.
* `sourcetype = linux_syslog`: Assigns a distinctive sourcetype to parse and filter system-level events separately from authentication events.

---

#### Step 3: Save and Exit Nano

* Press `Ctrl + O`, then hit `Enter` to write the changes.
* Press `Ctrl + X` to exit the text editor.

---

#### Step 4: Restart Splunk Universal Forwarder

Reload the forwarder daemon to apply the newly configured stanza:

```bash
sudo /opt/splunkforwarder/bin/splunk restart
```

---
### 9. Verify and Query System Logs in Splunk

Verify real-time ingestion of `/var/log/syslog` by querying system events and generating custom syslog messages from the Ubuntu terminal.

---

#### Step 1: Query All Ingested System Logs

In the Splunk **Search & Reporting** app, execute the baseline search to verify all incoming syslog streams:

```spl
index="linux" sourcetype="linux_syslog"
```

**Description:**  
Retrieves all general system, service, and kernel events ingested from the monitored `/var/log/syslog` file.

---

#### Step 2: Filter by System Activity (Reboot & Cron)

Narrow down events by specific system operations using keyword filters:

* **Filter Reboot and System Startup Events:**
  ```spl
  index="linux" sourcetype="linux_syslog" "reboot"
  ```
  *Description:* Identifies logs related to system restarts, shutdown signals, and kernel reboot triggers.

* **Filter Cron Task Executions:**
  ```spl
  index="linux" sourcetype="linux_syslog" "cron"
  ```
  *Description:* Displays automated background tasks and scheduled job executions initiated by the `cron` daemon.

---

#### Step 3: Generate a Manual Test Log via Ubuntu Terminal

To confirm real-time forwarding end-to-end, use the `logger` utility to inject an arbitrary syslog entry:

```bash
logger "this is a test for syslog."
```

**Command Breakdown:**
* `logger`: A built-in Linux command-line tool used to write custom entries directly into `/var/log/syslog` (and `/dev/log`).
* `"this is a test for syslog."`: The custom string payload written to the system log.

---

#### Step 4: Validate Custom Log Ingestion in Splunk

Return to the Splunk search bar and query for the injected test string:

```spl
index="linux" sourcetype="linux_syslog" "this is a test"
```

**Description:**  
Searches for the manual message injected via the `logger` command, validating that the Universal Forwarder picks up newly appended syslog lines and streams them to the Splunk index in near real-time.

---

#### Disabling a Syslog Monitoring 

To stop monitoring any log path in Ubuntu, open `inputs.conf` in nano and set `disabled = true`:

```ini
[monitor:///var/log/syslog]
disabled = true
```

*Setting `disabled = true` halts data collection for that specific file without deleting the configuration stanza.*

### 12. Configure PowerShell Event Logging in `inputs.conf`

---

#### Step 1: Open Notepad with Administrative Privileges

1. Click the Windows **Start Menu** or press `Win + S`.
2. Type **Notepad**.
3. Right-click on **Notepad** and select **Run as administrator**.
4. Open the configuration file located at:  
   `C:\Program Files\SplunkUniversalForwarder\etc\system\local\inputs.conf`

---

#### Step 2: Add PowerShell Operational Monitoring Stanza

Paste the following configuration block into the file:

```ini
[WinEventLog://Microsoft-Windows-PowerShell/Operational]
disabled = 0
index = main
renderXml = true
```

**Configuration Breakdown:**
* `[WinEventLog://Microsoft-Windows-PowerShell/Operational]`: Targets the operational channel of Windows PowerShell event logs (Event IDs such as 4104 for Script Block Logging).
* `disabled = 0`: Enables active ingestion (`0` equates to active monitoring, identical to `disabled = false`).
* `index = main`: Routes all collected PowerShell events into Splunk's default `main` index.
* `renderXml = true`: Ingests events in structured XML format, ensuring clean field extraction and full script block payload visibility.

---

#### Step 3: Save and Apply

* Press `Ctrl + S` to save the file.
* Close Notepad.


### 13. Restart Splunk in PowerShell, Generate Encoded Command & Track in Splunk

---

#### Step 1: Restart Splunk Service in PowerShell

Open PowerShell as Administrator:

Open PowerShell (Run as administrator)  
↓  
Type command and press `Enter` ↵:
```powershell
restart-service splunkd
```
*(This restarts the Splunk daemon service to apply all new configuration changes)*

---

#### Step 2: Check Automatic Source Path Detection in Splunk

Go to Splunk Search & Reporting:

1. In the search bar, run:
```spl
index=main
```
2. On the left sidebar under **Selected Fields**, click on **source**.
3. Under the source list, the full PowerShell event log path will appear automatically:
   `source="WinEventLog:Microsoft-Windows-PowerShell/Operational"`
4. Click on this path to automatically filter and view all incoming PowerShell operational logs.

---

#### Step 3: Generate & Run Base64 Encoded Command

Open PowerShell and write:

```powershell
$text = "'Hello world'"
$encoded = [Convert]::ToBase64String([Text.Encoding]::Unicode.GetBytes($text))$encoded
```
*(Press `Enter` ↵ — this will generate your Base64 encoded string)*

Now run the encoded command:
```powershell
powershell -EncodedCommand $encoded
```

---

#### Step 4: Search & Verify in Splunk Search Bar

Go to the Splunk search bar and search:

**Option 1: Search for the specific executed command**
```spl
index=main source="WinEventLog:Microsoft-Windows-PowerShell/Operational" powershell -EncodedCommand "<paste_your_encoded_cmd_here>"
```
*(Note: Put your generated Base64 encoded string inside the quotes `" "`)*

**Option 2: Detect all encoded commands across the system**
```spl
index=main source="WinEventLog:Microsoft-Windows-PowerShell/Operational" powershell -EncodedCommand
```
*(Note: Even if you just type this without specifying the encoded text, it will display every encoded PowerShell command that was executed on the system)*
